# Phase 0 Design-Partner Target Pipeline

Research date: **2026-09-30**.

Purpose: identify organizations likely to encounter repeated AWS incidents, billing data and operational telemetry across multiple customer environments. This is a **public-source prospecting list**, not evidence that any organization has missed SLA credits or lacks an existing recovery process.

Direct SLA-recovery vendors from the competitive scan are excluded from the primary list because the immediate goal is customer/design-partner validation, not competitor outreach.

## Selection signals

A candidate is included when current public sources show several of:
- AWS managed services / operational responsibility;
- AWS FinOps / cloud financial management;
- AWS reseller / solution-provider relationship;
- multi-customer consulting;
- monitoring / incident-management responsibilities;
- a public business contact path.

Absence of an SLA-recovery offer in this limited scan is **not** treated as proof that none exists.

## Outreach order

Start with organizations where operational evidence and FinOps responsibilities visibly overlap: tecRacer, Cloudar, CloudNation, SPIRIT/21, Scale Factory and Skaylink.

Duckbill is especially valuable as an expert interview even if it is not a pilot customer. QyrosCloud and Noventiq are useful additional pipeline coverage.

The order above is an outreach hypothesis only; actual responsiveness and access to real cases should replace it immediately.

## Qualification signal

A conversation is valuable only if it can answer factual Phase 0 questions. A **design-partner commitment** requires willingness to:
1. discuss the current SLA-credit process;
2. identify at least one real AWS incident or representative case;
3. provide a safely redacted evidence set for a manual audit, or explain exactly why that is impossible;
4. review the deterministic result;
5. optionally submit a resulting claim themselves if still within deadline and internally approved.

“Interesting idea” does not count.
